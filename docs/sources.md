# Sources: Remotion skills and OpenCode V2 agents

## Install Remotion skills locally

| Situation | Command to run from the project root | Source |
| --- | --- | --- |
| No Remotion dependency yet; install the full skill pack for OpenCode | `npx skills add remotion-dev/skills --agent opencode --skill '*' --yes` | [Remotion install guide](https://www.remotion.dev/docs/ai/skills), [Skills CLI options](https://github.com/vercel-labs/skills/blob/main/docs/commands.md#skills-add) |
| Existing Remotion project | `npx remotion skills add` (later: `npx remotion skills update`) | [Remotion CLI reference](https://www.remotion.dev/docs/cli/skills) |
| Scaffolding a new Remotion app | `npx create-video@latest --skills` | [create-video reference](https://www.remotion.dev/docs/cli/create-video#--skills) |
| Prefer the GitHub CLI | `gh skill install remotion-dev/skills` | [Remotion install guide](https://www.remotion.dev/docs/ai/skills) |

The Skills CLI is project-local by default; omit `--global`. Its documented OpenCode project target is `.agents/skills/`; the Remotion CLI also installs there and adds Claude compatibility links. The current Skills CLI README requires Node.js 22.20 or later. Use `npx skills add remotion-dev/skills --list` to check the published IDs before choosing a subset; Remotion’s docs and pack README are not always in sync. For reproducibility, the Skills CLI supports pinning the source to a tag or full commit; keep the generated `skills-lock.json` if using that workflow. [Skills CLI README](https://github.com/vercel-labs/skills#install-a-skill) · [Target paths](https://github.com/vercel-labs/skills/blob/main/docs/agents.md) · [Source formats](https://github.com/vercel-labs/skills/blob/main/docs/commands.md#source-formats) · [Official published pack](https://github.com/remotion-dev/skills)

OpenCode also discovers `.opencode/skills/<id>/SKILL.md` natively. For a manual install, copy the whole upstream skill directory, not just `SKILL.md`; its supporting files are resolved relative to that directory. Use only one copy per ID: `.opencode/skills` takes precedence over `.agents/skills`, so a stale native copy can mask an upstream update. In OpenCode V2, prompt with `@remotion-best-practices` or ask an agent to call the `skill` tool by ID; the slash examples in Remotion’s general-purpose docs are not needed for V2 loading. [OpenCode V2 Skills](https://opencode.ai/docs/skills#loading) · [Precedence](https://opencode.ai/docs/skills#precedence) · [Remotion skill catalog](https://www.remotion.dev/docs/ai/skills#available-skills)

## OpenCode V2 project agents and inheritance

- Put a named reusable profile in `.opencode/agents/<id>.md`, with `description` and `mode` in frontmatter and the system prompt in the body. Alternatively define it under `agents` in `opencode.jsonc`. `primary` runs the main session, `subagent` runs only in a child session, and `all` supports both. `default_agent` picks a visible primary-capable agent for sessions without a saved choice; it does not replace the agent on an existing session. [OpenCode V2 Agents](https://opencode.ai/docs/agents)
- There is no documented `extends` field or inheritance from an arbitrary named agent. Definitions with the **same ID** merge in configuration order; later scalars replace earlier values, request maps merge by key, and permission rules append. This also lets a project refine `build` without defining a new profile. Direct config files merge from distant directories toward the working directory, followed by discovered `.opencode/opencode.json(c)` files in the same order; managed configuration can override project settings. Markdown agent discovery runs from the working directory to the project root. [Agent merging](https://opencode.ai/docs/agents#merging) · [Config locations](https://opencode.ai/docs/config#locations)
- A child starts with fresh conversation context and its own configured permissions. The parent’s `subagent` permission controls which children it can launch. A child without a configured model inherits the parent session’s model; selecting a primary agent does not change a session’s stored model. Give children a self-contained brief rather than relying on parent history or system text. [Agent modes and models](https://opencode.ai/docs/agents#options)
- Put shared project guidance in root `AGENTS.md` rather than duplicating it in every agent. A custom `system` replaces the provider’s base prompt, not project instructions or skill guidance. OpenCode combines applicable instruction files; it does not automatically resolve contradictions. Skills are available on demand, subject to the selected agent’s `skill` permissions; installing a skill does not inject its full text or bind it to a specific agent. [Agent system prompt](https://opencode.ai/docs/agents#system) · [OpenCode V2 Instructions](https://opencode.ai/docs/instructions) · [Skill permissions](https://opencode.ai/docs/skills#permissions)

**Recommendation:** Install the official pack into `.agents/skills/` from the project root using the OpenCode-targeted Skills CLI command above, even before scaffolding a Remotion app. Keep project-wide conventions in `AGENTS.md` and role-specific prompts in `.opencode/agents/`. Have Remotion agents load `remotion-best-practices` when unsure or the narrower skill for the task; leave child `model` unset unless a specific model is required. Avoid duplicating upstream skill text in prompts or relying on a named-agent inheritance mechanism.
